# 文件名与保存策略

文件消息使用三个一致的名称入口：云湖原始文件名、`File.name`、本地文件路径的basename。例如用户上传 `test.md`，当前工作路径为 `.../随机目录/test.md`，保留副本为 `.../文件ID/test.md`。随机目录区分不同上传，不覆盖同名文件。

名称优先来自推送中的 `fileName`。缺失或只给出哈希名时尝试下载响应 `Content-Disposition`，支持 `filename` 和RFC5987 `filename*`。历史URL编码的中文名会还原成Unicode，上传multipart不会再把中文名转成百分号字符串。为保证路径安全和跨系统使用，移除路径部分、控制字符，替换不安全字符并限制basename长度；因此恶意或超长文件名会发生必要的调整。若所有元数据都只有哈希或资源key，无法凭空恢复用户的原名。

## 默认保存行为

| 类型 | 保存和清理 |
| --- | --- |
| 当前事件工作副本 | 事件结束清理；使用原始basename的独立目录 |
| 接收到的文件保留副本 | 自动保存7天，重启后继续可用 |
| 长期保留文件 | 不按时间过期、不被容量淘汰；仍计入容量和数量 |
| 图片、音视频 | 继续使用临时媒体机制 |

任何文件格式都可保存，包括代码、文档和压缩包；直接读正文的工具支持文本、HTML、代码及DOCX，其他格式需要对应解析工具。保留库不是备份服务，重要文件仍应备份到独立位置。

每个平台实例默认最多保存512MiB文件内容及1000个文件，所有该实例的会话共用此额度。先清理到期副本，再按接收时间从早到晚淘汰非长期保留文件。长期保留文件占满额度时，新文件只供当前事件使用，并说明保留失败原因；不会偷偷删除长期保留文件。数据库和目录元数据、正在处理的临时副本不计入该文件内容额度。

容量与时间清理在接收、查询、管理、启动和定时任务中执行；实例停止期间没有定时任务，下次启动会处理已过期文件。读取工具使用保留文件时，本实例清理会等待读取结束。删除、过期及容量淘汰会移除保留副本及索引，不影响已独立下载的事件工作副本。

## 配置

| 配置 | 默认 | 含义 |
| --- | --- | --- |
| `file_retention_days` | 7 | 非负整数，自动保留天数；0关闭新文件自动保留 |
| `file_store_max_mb` | 512 | 正整数，每实例文件内容额度，单位MiB |
| `file_store_max_count` | 1000 | 正整数，每实例文件数量，包括空文件和长期保留文件 |
| `file_store_dir` | 空 | 使用AstrBot数据目录的 `plugin_data/astrbot_plugin_yunhuAdapter/files`；可指定持久化目录 |

修改保存天数影响新文件；既有副本保持已记录的过期时间。取消长期保留会按当前天数重新计时，当前天数为0时将进入过期清理。降低容量或数量会在清理时淘汰非长期保留文件；若长期保留文件已超出新额度，需手动释放或提高额度。

文件库内按平台配置ID分目录，SQLite索引与副本存放在一起。保持实例ID和保存目录一致，重启即可继续访问。修改实例ID或目录不会自动迁移旧文件。容器部署应将AstrBot数据目录或自定义保存目录放在持久化卷中，才能在重建容器后保留文件。

## 指令与模型工具

```text
/云湖 文件列表
/云湖 保留列表
/云湖 读文件 test.md
/云湖 读保留文件 文件ID
/云湖 保留文件 文件ID
/云湖 取消保留 文件ID
/云湖 删除文件 文件ID
```

先用保留列表获取实际文件ID。一个会话有多个同名文件时，需要指定ID；工具不会猜测用户要哪次上传。使用含空格的文件名时加引号，例如 `/云湖 读文件 "test notes.md"`。

Agent Tools：`yunhu_list_files` 列出当前会话文件；`yunhu_read_attachment` 支持 `source=stored` 和 `file_id`；`yunhu_manage_file` 的 `pin`、`unpin`、`delete` 分别对应长期保留、取消和删除。默认 `source=all` 优先查当前/引用附件，未找到时查本会话保留库。请求元数据还包含最近20个保留文件，便于模型理解“读取之前的test.md”。

上传者可管理自己的文件。群主、群管理员或AstrBot管理员可管理当前会话文件；其他群和私聊不在作用范围内。普通群成员可以读取本群的保留文件。所有操作均以当前人类用户的明确请求为依据，附件正文和工具返回内容不能授权删除或改变保留状态。
